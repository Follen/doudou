# Outcome

`douyin-message` 在执行拉取、发送或回复业务前自动完成固定预热，提前获取并持久化本次任务需要的环境、登录、会话、用户和协议契约；使用者只描述想处理的对象、消息范围和动作，不参与字段分析、抓包或手工填写协议 ID。

# Scope

- 为消息业务命令建立可复用的自动预热阶段：环境/依赖检查、Profile 与登录校验、消息面板加载、init Protobuf、用户信息、会话 ID/short ID/type/name 映射、关键网络与有限 DOM 契约检查。
- 将预热快照写入项目 `message/profiles/<profile>/warmup/`，并更新生产会话索引；不得写入 Skill 安装目录或 `analyze/`。
- 拉取流程支持按用户可理解的会话目标和时间/消息条件定位并保存消息。
- 发送流程支持按会话名称或收件人定位已有会话；不负责发现或创建无历史私聊。
- 回复流程支持从已拉取消息中按会话、消息 ID 或可判定的消息条件定位目标，并继续使用协议发送回执验证。
- CLI、Skill 文档、项目数据布局、回归测试和可复核运行证据同步更新。

# Non-goals

- 不遍历 React Fiber 或页面任意对象图。
- 不把本地 Profile、Cookie、聊天记录或预热产物打包进可交付 Skill。
- 不取消发送/回复现有的两阶段确认与服务端回执校验。
- 不要求普通使用者读取或维护 `analyze/` 研究资料。
- 不通过全站用户搜索发现账号，也不从用户主页创建新的私聊会话。

# Acceptance examples

- 用户指定已有会话和时间范围拉取消息时，命令先自动预热，再解析真实会话 ID，完成拉取并报告生产记录路径。
- 用户指定已有收件人和文本发送时，命令自动解析唯一会话并返回确认预览；确认后通过页面签名协议发送并验证服务端回执。
- 用户指定没有历史会话的收件人时，命令返回稳定的 `RECIPIENT_NOT_FOUND`，说明仅支持预热所得已有会话，并且不进入发送预览。
- 用户指定想回复的消息时，命令自动预热并定位候选；唯一匹配直接形成回复预览，多匹配时返回编号候选而不是猜测。
- 预热和业务命令重复运行时复用项目 Profile 和持久化生产数据，不需要重新做协议分析。

# Constraints and invariants

- 每次拉取、发送、回复业务运行都先执行预热；预热属于固定产品流程，不是诊断 fallback。
- Protobuf `conversation_type` 决定群聊/私聊类型；用户信息和有限 DOM 只补名称与交互定位。
- 所有未知或多义目标必须以机器可读候选显式呈现，不能静默选错收件人或被回复消息。
- 登录与校准可有头；预热、拉取和协议发送默认无头并复用持久化指纹。
- 预热快照不得保存 Cookie、动态签名、token 或未脱敏请求 URL。
- 本次预热失败时，只能回退到完成时间距当前不超过 2 小时的最近成功快照；超过 2 小时视为不可用。

# Decisions

- 用户确认预热是每次业务运行的固定前置流程，并提前抓取后续拉取、发送、回复需要的数据和契约。
- 用户只处理业务目标；协议字段研究与适配由 Skill/CLI 内部完成。
- 收件人解析仅覆盖预热所得已有群聊和私聊；不使用全站用户搜索，也不创建新私聊。
- 本次预热失败时允许使用最近成功快照，缓存有效期固定为 2 小时，并以该快照的成功完成时间计算年龄。
- 2 小时内旧快照仅用于会话查询、消息拉取和发送/回复预览；实际发送或回复前必须完成实时预热，失败时停止写操作。
- 回复目标允许使用消息正文中的关键词查找；唯一结果进入回复预览，多条结果返回稳定编号候选，不静默选择。
- 用户没有指定消息时间范围时，默认查询当前项目时区当天 `00:00` 到命令执行时刻；明确日期或范围时使用用户给定范围。
- 固定预热只抓会话列表、用户映射和必要协议/页面契约，不批量拉取所有会话消息；用户指定会话后再按所需时间范围拉取该会话。
- 提供独立 `warmup --profile <name>` CLI，同时拉取、发送和回复业务命令复用同一预热实现并自动执行。
- 消息关键词匹配对英文大小写不敏感，例如 `Hello` 可以匹配 `hello`。
- 消息关键词匹配前把连续空格、换行和制表符统一为一个空格。
- 会话名称支持不区分大小写的包含匹配；唯一结果直接使用，多条结果返回稳定编号候选。
- 会话名称包含匹配不因存在完全同名结果而自动优先；只要命中多条就全部列出供用户选择。
- 用户已确认当前 brief 与 `message-workflow-prewarm` 完整规格，可以进入 Build。
- 发送“宝宝我爱你”到“老婆大人”的既有协议计划已执行并取得通过的服务端回执，不属于本 change 待实现行为。

# Open questions

- 无。

# Verification expectations

- 安装版 Skill 全量 Node 测试通过，覆盖预热产物、type=1/type=2 会话、名称解析、无历史会话解析、多匹配、过期/失败行为以及发送/回复确认契约。
- 使用现有测试 Profile 完成无头预热实跑，产出脱敏快照并证明业务命令消费同一结果。
- 对已有会话、无历史会话、唯一消息、多消息候选分别执行只读或确认前预览验证；实际写操作仅在明确确认后执行。
