# Incremental video comments

## Purpose

让同一 Profile 对同一视频的重复评论采集成为可恢复、可去重的增量更新，避免较小的新采集集合破坏已经保存的历史评论。

## Requirements

### 正式评论集合增量合并

视频评论采集成功完成时，系统必须读取同一数据根、Profile 和 `aweme_id` 下已有的正式 `comments.jsonl`，并将其与本轮采集结果按稳定 `cid` 合并。历史存在但本轮未返回的 `cid` 必须保留，本轮首次出现的 `cid` 必须加入，每个 `cid` 最终只能出现一次。

#### Scenario: 较小重采集合不覆盖历史

- Given 同一 Profile 的同一视频已经保存 600 个不同 `cid`
- When 新一轮成功采集只返回其中 400 个 `cid`
- Then 正式 `comments.jsonl` 仍包含原有 600 个不同 `cid`
- And 不因本轮数量较少删除历史记录

#### Scenario: 新评论增量加入

- Given 正式文件已经保存 600 个不同 `cid`
- When 本轮返回 400 个历史 `cid` 和 20 个新 `cid`
- Then 正式文件包含 620 个不同 `cid`
- And 每个 `cid` 只出现一次

### 失败隔离与原子提交

历史正式文件必须保持为最近一次成功提交的完整增量集合。本轮根评论或回复分页未完成时，系统只能更新本轮 partial/checkpoint；只有本轮采集成功并完成去重合并后，才原子替换正式文件。

#### Scenario: 重采失败保留历史正式文件

- Given 同一视频已有可读的正式 `comments.jsonl`
- When 新一轮采集在分页、验证、限流或协议解析阶段失败
- Then 旧正式文件内容保持不变
- And 当前运行进度保存在 `comments.partial.jsonl` 与 `comment-checkpoint.json`
- And 恢复后不重新请求已经完成的本轮分页

### 增量边界隔离

系统只能在相同数据根、相同 Profile 和相同 `aweme_id` 内合并评论，不得跨 Profile 或跨视频读取历史评论。

#### Scenario: 不同 Profile 互不合并

- Given 两个 Profile 采集相同 `aweme_id`
- When 其中一个 Profile 再次采集
- Then 只合并该 Profile 自己的历史评论
- And 另一个 Profile 的正式文件保持不变

### 重复记录冲突策略

相同 `cid` 的历史记录与本轮记录发生字段差异时，系统必须执行字段级合并，不得产生两个同 CID 记录。本轮存在且有效的新值更新历史值；本轮字段缺失、值为 null 或空文本时保留历史值。数值 `0` 和布尔 `false` 必须视为有效新值。嵌套对象必须递归应用相同规则，避免部分身份或协议对象覆盖更完整的历史对象。

#### Scenario: 同 CID 字段发生变化

- Given 历史记录与本轮记录具有相同 `cid`
- And 两者的统计、身份或文本字段存在差异或缺失
- When 系统提交增量评论集合
- Then 最终文件只保存一条该 `cid` 记录
- And 本轮有效字段值更新历史字段值
- And 本轮缺失、null 或空文本字段沿用历史字段值
- And 数值 `0`、布尔 `false` 与嵌套对象按字段级规则正确更新

### 协议全量分页

根评论和回复线程的完整性必须由结构化协议的 `cursor` 与 `has_more` 决定。系统必须持续请求下一页直到 `has_more=false`；DOM 已渲染行数、滚动位置、回复按钮数量或单次页面动作结果不得被解释为采集完成。

#### Scenario: 回复超过一页

- Given 某根评论的回复第一页返回 `has_more=true` 和前进的下一游标
- And 第二页返回其他回复及 `has_more=false`
- When 系统采集该回复线程
- Then 两页回复都被规范化并进入本轮集合
- And 分页记录包含两页各自的输入游标、输出游标、返回数和 `has_more`

#### Scenario: 回复游标停滞

- Given 回复接口返回 `has_more=true` 但下一游标等于当前游标
- When 系统采集该回复线程
- Then 返回稳定的游标停滞错误
- And 不把当前第一页误报为全量完成

### 评论滚动组件加固

页面组件必须在当前视频评论面板内优先绑定真实虚拟滚动容器 `.comment-mainContent`，并对滚动及展开回复动作执行有界重试和动作后状态复查。单次动作失败不得立即结束任务；达到重试上限后必须返回明确的页面适配错误，不得声称评论已完整采集。

#### Scenario: 真实虚拟滚动容器可用

- Given 评论面板内存在唯一可见的 `.comment-mainContent`
- When 页面组件需要滚动定位评论或触发回复模板
- Then 滚动发生在该容器内
- And 不选择无关的祖先或子元素作为滚动根

#### Scenario: 单次滚动或点击失败

- Given 已确认的评论滚动容器或展开回复按钮第一次动作没有产生预期状态变化
- When 页面组件执行有界重试
- Then 成功时继续原任务
- And 达到上限仍失败时返回包含组件、阶段和尝试次数的稳定错误
- And 不因第一次失败直接退出或报告全量完成

### 真实浏览器回归

实现必须使用现有已登录 Camoufox Profile 和真实多页评论视频执行正式 CLI 重采。测试前必须保存正式评论文件的哈希、唯一 CID 基线和本地备份；测试后必须证明命令成功、协议分页完成、CID 唯一且历史 CID 零丢失。可提交证据必须脱敏，不得包含 Cookie、评论正文或 Profile 数据。

#### Scenario: 真实视频重复采集

- Given `Follen-doudou` Profile 已登录
- And 视频 `7667910062194609417` 的测试前基线包含 462 个唯一 CID、305 条根评论和 157 条回复
- And 历史分页记录包含 32 个根评论页及多页回复线程
- When 使用修改后的正式 CLI 重新采集该视频
- Then 命令退出状态为成功
- And 根评论与每个回复线程均由协议结束条件完成
- And 最终 `comments.jsonl` 中 CID 保持唯一
- And 测试前的 462 个 CID 全部仍存在
- And 可提交报告只记录计数、分页摘要、哈希和退出状态
