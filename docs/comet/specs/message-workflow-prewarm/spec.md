# 消息业务预热与目标解析

## 目标

`doudou` 必须把协议发现和页面契约采集内建为拉取、发送、回复的固定预热阶段，使调用者能够用业务目标驱动完整流程，而不需要分析 Protobuf、抓包或手工查找会话 ID。

## 固定预热

1. 每次拉取、发送或回复业务运行开始时，CLI 必须检查 Node、npm、Playwright、匹配版本 Chromium、项目目录、Profile、指纹和登录状态。
2. CLI 必须使用选定 Profile 打开消息面板，并等待网络采集稳定。
3. CLI 必须解析 init 与相关 IM Protobuf，保留 `conversation_id`、`conversation_short_id`、`conversation_type`、排序信息和可用显示信息。
4. type `1` 的 direct ID 必须接受服务实际使用的 `0:1:<uid>:<uid>` 格式；type `2` 群聊继续使用服务返回的数字 ID。
5. CLI 必须采集用户信息 JSON，并用 direct ID 的另一方 UID 补充备注名或昵称；当前账号 UID 不得被误用作收件人名称。
6. CLI 可以读取明确限定的 DOM 属性、头像结构、搜索框和新建聊天控件来补充名称与交互定位，但不得遍历 React Fiber 或任意对象图。
7. CLI 必须把脱敏预热快照和最新会话索引写入 `message/profiles/<profile>/`，其中不得包含 Cookie、token、动态签名或完整敏感查询参数。
8. 固定预热只抓会话列表、用户映射和必要协议/页面契约，不得批量拉取所有会话消息。CLI 必须提供独立 `warmup --profile <name>` 命令，业务命令也必须自动调用同一预热实现。

## 业务目标解析

1. 拉取、发送和回复命令必须能够从最新预热结果按真实 ID、编号或用户可读名称解析会话。
2. 唯一匹配可以直接进入下一只读步骤或确认预览；多个匹配必须返回稳定编号、类型、名称和 ID，等待调用者选择。
3. 会话名称匹配必须使用 Unicode 大小写折叠并统一连续空白，支持包含匹配；只有一个包含结果时可以直接使用，多个包含结果时必须全部返回候选。即使其中一项与输入完全同名，也不得优先自动选择。
4. 消息面板右上角加号实际是“发起群聊”，其用户搜索用于邀请互相关注的人建群，不得当作新建一对一私聊入口。
5. 收件人解析仅覆盖本次预热所得已有会话。CLI 不得回退到全站用户搜索，不得从用户主页创建新私聊；没有已有会话时必须返回 `RECIPIENT_NOT_FOUND` 并停止在确认预览之前。
6. 消息拉取必须接受明确时间范围，并把消息、未知字段和冲突写入对应生产会话目录。
7. 回复目标可以由会话 ID/名称、消息 ID、完整正文或正文关键词指定。关键词只命中一条消息时形成引用回复预览；命中多条时必须返回稳定编号、消息 ID、发送者、时间和正文摘要供调用者选择，不得静默选择。
8. 消息正文关键词匹配必须使用 Unicode 大小写折叠，英文及其他有大小写形式的字符不区分大小写。
9. 消息正文和关键词在匹配前必须把连续空格、换行和制表符统一为一个空格，并去除首尾空白；内部标点和其他字符保留。
10. 用户未提供消息时间范围时，CLI 必须使用当前项目时区当天 `00:00` 到命令执行时刻；用户明确给出日期或范围时必须使用该范围。
11. 用户选定会话后，CLI 才按所需时间范围拉取该会话消息并执行消息条件匹配。

## 写操作确认与验证

1. 发送和引用回复必须先返回包含 Profile、会话名称、真实会话 ID/type、目标消息（回复时）和正文的 `confirmation_required` 预览。
2. 只有匹配 `plan_id` 的显式确认才能执行写操作。
3. 执行后必须校验 HTTP 状态、Protobuf 状态、服务结果、客户端消息 ID 回显和会话匹配，并保存请求、响应、receipt 与 verification。

## 重复运行与失败

1. 预热是每次业务运行的固定阶段；运行时可以利用同一项目下已持久化的数据做增量合并，但不能跳过本次环境、登录和契约有效性检查。
2. 预热、目标解析或协议契约不满足时必须返回稳定错误码、已完成步骤和修复/重试信息，不得转而要求使用者做字段分析。
3. 本次预热失败时，CLI 可以回退到最近一次成功快照，但快照完成时间距当前不得超过 2 小时；年龄从成功完成时间计算，超过 2 小时必须返回预热失败且不得消费该快照。
4. 使用旧快照时，输出必须明确标记 `warmup_source: stale_cache`、快照完成时间和年龄。
5. 2 小时内旧快照只允许用于会话查询、消息拉取和生成发送/回复确认预览。用户确认实际发送或回复后，CLI 必须重新完成实时预热；实时预热失败时必须停止写操作，不得使用旧快照发送。

## 数据边界

1. Profile 与生产消息、预热和发送记录只存在调用项目的 `profile/` 与 `message/`。
2. 可交付 Skill 只包含 CLI、运行代码、文档、测试和必要依赖定义，不包含任何用户 Profile、聊天记录或研究目录。
