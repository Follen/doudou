# Outcome

同一 Profile 对同一视频重复采集评论时，正式评论存储按稳定 `cid` 去重增量合并，不再用本轮较少的结果整体覆盖历史完整数据。

# Scope

- 在视频评论采集成功提交前读取同一 Profile、同一 `aweme_id` 已有的 `comments.jsonl`。
- 将历史正式评论与本轮完整采集结果按 `cid` 合并，每个 `cid` 最终只保留一条记录。
- 保持中断恢复检查点只描述当前采集运行；本轮失败时继续保留上一次成功的正式评论文件。
- 加固评论页面组件：优先识别真实评论滚动容器 `.comment-mainContent`，滚动或展开回复按钮单次失败时进行有界重试，不因一次页面动作失败提前结束。
- 用协议 `cursor/has_more` 完整采集根评论和每个回复线程；页面滚动只用于打开评论面板、捕获请求模板或定位写操作目标，不作为评论完整性的判断依据。
- 增加存储单元测试和视频采集回归测试，覆盖历史 600 条、本轮 400 条时最终不少于历史集合，以及新增评论的增量写入。
- 更新评论存储的运行时说明。

# Non-goals

- 不把不同 Profile 或不同视频的评论合并。
- 不根据本轮未返回判断评论已删除，也不从历史文件删除旧评论。
- 不改变评论根页、回复页的协议分页、限流、验证或错误分类。
- 不通过解析虚拟滚动 DOM 文本来代替评论协议分页。
- 不增加评论历史版本库或逐次备份目录。

# Acceptance examples

- 给定昨天同一视频已保存 600 个不同 `cid`，今天成功采到其中 400 个且没有新评论，完成后 `comments.jsonl` 仍包含 600 个不同 `cid`。
- 给定历史 600 个 `cid`，本轮返回其中 400 个并新增 20 个，完成后正式文件包含 620 个不同 `cid`。
- 给定历史正式文件存在，而本轮在分页或回复采集阶段失败，旧 `comments.jsonl` 内容保持不变，本轮进度只写入 partial/checkpoint 文件。
- 给定历史或本轮内部出现重复 `cid`，最终正式文件中该 `cid` 只出现一次。
- 给定根评论或回复接口第一页返回 `has_more=true`，采集必须持续使用下一游标，直到 `has_more=false`，不得只保存第一页。
- 给定评论列表使用 `.comment-mainContent` 虚拟滚动，页面组件能绑定该容器；滚动或展开按钮第一次动作失败时进行有界重试，成功后继续，不提前报告全量完成。
- 给定已登录的真实 `Follen-doudou` Profile 和已有 462 个唯一 CID 的视频 `7667910062194609417`，使用修改后的正式 CLI 重采后，协议分页必须真实到达 `has_more=false`，最终唯一 CID 数不得低于重采前基线，且历史 CID 不得丢失。

# Constraints and invariants

- 增量边界固定为当前数据根、当前 Profile 和当前 `aweme_id`。
- 正式 `comments.jsonl` 继续使用原子写入，不得原地追加导致半行或部分提交。
- `comments.partial.jsonl` 与 `comment-checkpoint.json` 继续服务于单次未完成运行，不得把历史正式集合伪装成本轮分页进度。
- 评论父子 ID、身份补齐和 schema 字段保持现有结构。
- 评论完整性由协议分页结束条件决定；DOM 中已渲染的行数、滚动位置或按钮数量不得作为完成条件。
- 页面动作重试必须有明确上限，动作后重新校验组件状态，不得无限点击或无限滚动。
- 存储层不得依赖浏览器，采集编排继续位于 `reads`。

# Decisions

- 用户明确要求评论存储采用按 `cid` 去重增量合并，禁止用本轮结果硬覆盖历史正式集合。
- 本轮未返回的历史 `cid` 仍保留；系统不把“未返回”解释为已删除。
- 采集失败不发布合并结果，沿用旧正式文件并保留当前运行 checkpoint。
- 用户补充要求修复评论虚拟滚动容器识别、单次滚动/点击失败提前退出和回复分页只取第一页的问题。
- 正式读取继续采用现有协议优先架构；页面组件加固不把全量采集降级为 DOM 抓取。
- 用户选择同 `cid` 字段级合并：本轮有效新值更新历史值，本轮缺失、null 或空文本字段保留历史值；数值 `0` 和布尔 `false` 是有效新值，不能被当作缺失。
- 嵌套对象按相同规则递归合并，避免本轮身份或协议子对象缺字段时丢失历史信息。
- 用户要求必须完成真实浏览器测试，不能只用 fixture 或 mock 验收。
- 本地真实回归目标使用 `Follen-doudou` Profile 的视频 `7667910062194609417`；当前脱敏基线为 462 个唯一 CID、305 条根评论、157 条回复，历史运行包含 32 个根分页和多页回复线程。

# Open questions

# Verification expectations

- 运行评论存储与视频采集相关 Python 测试。
- 运行完整 `docs/verification/tests` 与 Ruff。
- 验证原子提交、失败保留旧文件、跨 Profile/视频隔离和重复 `cid` 唯一性。
- 使用临时 fixture 构造 600 条历史加 400 条本轮子集，并核对最终唯一 CID 数为 600；再加入 20 条新 CID，核对为 620。
- 使用多页根评论和多页回复 fixture 验证游标持续推进到 `has_more=false`，并验证游标停滞与页数上限仍明确失败。
- 为 `.comment-mainContent` 选择、滚动有界重试、按钮点击有界重试和动作后状态复查增加页面组件测试。
- 真实测试前记录正式 `comments.jsonl` 的 SHA-256、唯一 CID 集合和计数，并建立本地备份；使用修改后的正式 CLI 与现有已登录 Profile 重采同一视频。
- 真实测试后核对退出状态、根评论/回复分页均以 `has_more=false` 结束、最终 CID 唯一、历史 CID 零丢失、最终计数不低于 462，并记录脱敏验证报告；不得把 Cookie、评论正文或 Profile 数据提交到 Git/npm。
